# 空气质量数据分析项目：阶段总结与下一步计划

> 覆盖周期：第 1 周（PySpark 与 ETL 管道）+ 第 2 周（MySQL 建库与数据入库）
> 项目主题：基于 Spark 的城市空气质量多维分析（20 城 × 2022-2024 三年）

---

## 一、这个阶段我做了什么

### 1.1 数据集概况

| 项目 | 内容 |
|---|---|
| 数据源 | 全国城市空气质量实时发布数据（中国环境监测总站格式） |
| 时间范围 | 2022-01-01 ~ 2024-12-31，整整 3 年，**1096 个按天分文件的 CSV** |
| 单文件形状 | 360 行 × 378 列（24 小时 × 15 个指标 type + 375 个城市各占一列） |
| 15 个指标 | AQI、PM2.5(24h)、PM10(24h)、SO2(24h)、NO2(24h)、O3 / O3-8h(24h)、CO(24h) |
| 分析范围 | 按学习计划锁定 20 个代表性城市（4 直辖市 + 省会 + 计划单列市 + 重点城市） |
| 原始问题 | 超宽表（375 城横排）、列名含点号（PM2.5）、负值脏数据、文件孤岛 |

### 1.2 第 1 周：PySpark 与 ETL 管道

**动作 1 —— 环境搭建**：JDK 8 + 下载 winutils.exe/hadoop.dll 配置 HADOOP_HOME + pip 安装 pyspark 3.5.6（清华镜像）。排错经历：`Python worker crashed` 定位为运行环境对 JVM↔Python 进程通信的干扰，本机终端直跑正常。

**动作 2 —— 长宽表转换**（[action2_pivot_wide.py](action2_pivot_wide.py)）：
- `stack(375, ...)` 把 375 个城市列熔化成 (city, value) 长表 → 135,000 行
- `pivot("type", [...])` 把 15 个指标 type 转回列 → **9000 行宽表**（24h × 375 城）

**动作 3 —— 清洗 + 窗口函数**（[action3_clean_window.py](action3_clean_window.py)）：
- 负值 → null、`dropna` 丢弃全空行（9000 → 8231 行）
- `Window.partitionBy(city).orderBy(date,hour).rowsBetween(-23, currentRow)` 计算 PM2.5 24 小时滚动均值
- 发现：单天数据滚动窗口不满 24 行，与源数据 `PM2.5_24h`（跨天窗口）存在口径差异

**动作 4 —— 3 年全量 ETL**（[action4_multi_year_etl.py](action4_multi_year_etl.py)）：
- 谓词下推优化：先选 20 城列再 stack，熔化量从 1.48 亿行降到 **783 万行**（-95%）
- 产出 **522,191 行**事实数据（1097 天 × 24h × 20 城），清洗掉 29 个全空行
- 质检：自算滚动均值 vs 源数据 `PM2.5_24h`，北京 26,109 行**平均绝对误差仅 0.38**；2024-12-31 逐小时吻合
- 输出 parquet（列存、保 double 类型、8 分区）→ `data/interim/multi_year_cleaned`

**关键踩坑（面试可讲）**：
1. 列名 `PM2.5` 被 Spark 解析为嵌套列 → 必须反引号 `` F.col("`PM2.5`") ``
2. 惰性执行下重复扫描 1096 个 CSV → 中间结果 `cache()`
3. MySQL 列名不允许点号 → 入库前统一映射蛇形命名

### 1.3 第 2 周：MySQL 建库与数据入库

**建库**（[database.sql](../../database.sql)）：`air_quality` 库 7 张表
- `air_quality_detail`：52 万行事实表，date 用 **DATE 类型**（MONTH()/WEEKDAY() 直接可用），唯一键 (date,hour,city) 防重
- 字典表：`city_info`（20 城省份/经纬度/区域）、`aqi_level`（6 级国标含可视化颜色）
- 结果表（预留空表等算法填）：`city_cluster_result`、`cluster_center`（子系统三）、`anomaly_hourly`、`anomaly_events`（子系统四）

**入库**（[action5_to_mysql.py](action5_to_mysql.py)）：`df.write.jdbc()` 推送 522,191 行
- 入库转换：`'20220101'` 字符串 → DATE；PM2.5 → pm25 蛇形列名
- 性能：batchsize=5000 + `rewriteBatchedStatements=true`
- 密码走环境变量不落代码

**验证**：mysql 客户端直查——总行数 522,191 与 parquet 一致；北京 2022-01-01 恰好 24 行；`pm25_24h_rolling` 递减逻辑正确（hour2 = (37+35+35)/3 = 35.67）。

**阶段产出**：干净数据双底座——**Parquet（分析用）+ MySQL（查询/展示用）**。

## 二、接下来怎么做（短期计划，不含后端开发）

按依赖顺序排列，每步独立可验证：

### 第 1 步：子系统二 SQL 统计跑通（半天，最快见效）
在 MySQL 上把 5 条核心统计 SQL 逐个跑通并留存结果：
1. 季节对比（PM2.5 冬高夏低、O3 夏高冬低的反向趋势）
2. 昼夜 24 小时波动曲线
3. 城市 AQI 排行榜
4. 多城市月度趋势（北方组：北京/天津/济南/郑州）
5. 逐年优良天数占比（日 AQI ≤ 100 口径，先按天聚合再判断）

产出：`data/interim/sql_analysis/` 下每个查询一份 CSV 结果 + SQL 脚本存档。

### 第 2 步：首要污染物回填（半天）
用 Spark 按 IAQI 国标分段插值规则，对每行计算首要污染物，回填 `air_quality_detail.primary_pollutant` 列（建表时已预留）。之后"PM2.5 vs O3 频次演变"查询即可运行，验证文献结论"近年臭氧污染占比上升"。

### 第 3 步：子系统三 PCA + K-Means 聚类（1-2 天）
1. 从 detail 聚合 20 城 × 15 指标画像矩阵（全期 + 分季节共 3 个 batch）
2. StandardScaler 标准化 → PCA（累计方差 ≥85%，取 2-3 成分）→ K-Means（肘部法则定 k）
3. 看簇中心画像给簇命名（如"煤烟型/臭氧型/清洁型"）
4. 写 `city_cluster_result`（20 行/batch）+ `cluster_center`（k 行/batch）
5. 亮点分析：同一城市冬季 vs 夏季的簇归属变化表

### 第 4 步：子系统四孤立森林异常检测（1-2 天）
1. 特征 = 15 指标 + hour + 星期；IsolationForest(contamination≈0.01)
2. 写 `anomaly_hourly`（~52 万行分数明细，阈值可调不用重跑）
3. 连续异常 ≥6 小时合并为事件窗口，Z-score 归因定主控污染物
4. 写 `anomaly_events`（事件 + JSON 归因卡片）

### 第 5 步（可选增强）
- 日历热力图数据导出（城市 × 365 天 AQI 矩阵）
- 用静态 HTML + ECharts CDN 做一页离线大屏原型（读上面导出的 CSV/JSON，不需要任何后端）

### 3.2 每个图表的功能定义（数据来源 → 图表类型 → 交互）

| 编号 | 图表 | 数据来源 | 类型 | 交互 |
|---|---|---|---|---|
| ① | 季节对比 | SQL:季节 GROUP BY | 双系列柱状 | 切换指标(pm25/o3/aqi) |
| ② | 昼夜波动 | SQL:GROUP BY hour | 折线 | 悬浮显示各时刻均值 |
| ③ | 月度趋势 | SQL:city+月份 | 多折线 | 城市勾选框增减 |
| ④ | 中国地图 | city_info 经纬度 + AVG(AQI) | scatter-map | 点击联动③⑥，点色来自 aqi_level.color |
| ⑤ | 排行榜 | SQL:ORDER BY AVG(aqi) DESC | 横向条形 | 点击城市地图高亮 |
| ⑥ | 优良环形图 | 日聚合 + aqi_level | pie(doughnut) | 按年切换 |
| ⑦ | 首要污染物 | primary_pollutant 频次 | 堆叠柱/折线 | 年份切换 |
| ⑧ | PCA 散点 | city_cluster_result(batch) | scatter | 按 batch 切换季节，同城市冬季/夏季点连线 |
| ⑨ | 簇雷达 | cluster_center | radar | 选择簇显示/隐藏 |
| ⑩ | 异常事件 | anomaly_events | 表格卡片 | 点击展开 attribution JSON 归因详情 |
| ⑪ | 分数时间线 | anomaly_hourly | 折线+阈值线 | 拖动阈值重着色（对应 UPDATE is_anomaly） |

### 3.3 三个分析亮点的呈现方式

1. **季节反向趋势**：①中 PM2.5（冬季峰值）与 O3（夏季峰值）同图对比，一张图讲完"冬季煤烟 vs 夏季光化学"的故事
2. **季节聚类迁移**：⑧按 batch 切换，同一城市在冬季/夏季散点位置移动、颜色变化 → 直观展示"城市污染画像随季节改变"
3. **异常归因卡片**：⑩事件行展开后显示"主控污染物 PM2.5（Z=3.2）、次因 CO（Z=2.1）、持续 14 小时、峰值出现在 01-21 08 时"的结构化归因

### 3.4 无后端的静态原型实现路径

第 5 步产出的每个 SQL 结果导出为 JSON → 单个 HTML 文件内嵌 ECharts（CDN）→ 纯浏览器打开即可演示，交互（切换年份/城市/簇）全部用前端 JS 过滤实现。这可以做为毕业设计答辩的演示兜底方案，后续真接后端时接口字段一一对应。
